# 演示视频分镜（3 分钟）

课程要求（`results/_docx.txt:186`）：2–5 分钟演示，展示模型在**未参与训练的新样本**上的效果。
下面 11 个镜头全部用 `data/external/demo_shots/` 里的图，这些图都不在训练集里（网图 623 张、16chinese、
CNFOOD-241 的 OOD 集），所以"没参与训练"这句话可以放心讲。

录制方式：**自己录屏**（本机没有 ffmpeg / playwright，Edge 只能 headless 截图不能录）。
推荐 `Win + G`（Xbox Game Bar）或手机拍屏幕；窗口用 1360×900 左右，浏览器 F11 全屏，缩放 100%。

## 2. 口播稿（可直接念）

**1（0:00）** 食堂里想知道这盘菜多少热量，现在只能靠猜。我们做了一个网页：拍一张照片，给出菜名和热量区间。

**2（0:15）** 上面四个标签对应四种真实场景：单菜识别管 20 道最常见的菜；116 类管更宽的中餐和外餐；
食堂菜管 22 路（20 道菜 + 米饭 + 一个"其它中餐"兜底）；混合餐盘管一盘里好几样。

**3（0:35）** 这是酸辣土豆丝，网图，没参与训练。食堂模式给出 97.2%，150 到 210 千卡，按 150 克估。
注意阈值这里从 0.41 降到了 0.36——域判别器很确信这是食堂中餐，所以门控自动放宽，这是为了少误拒。

**4（1:05）** 红烧肉，99.5%，390 到 520 千卡。右边的份量可以切 0.7 倍、1.35 倍，只在前端重算，不重新推理。

**5（1:20）** 现在故意用错标签：地三鲜放到"单菜识别"里。模型说大概不是这 20 道菜，还给了换标签的按钮。
点一下，自动切到食堂菜，97.9%。这就是"三套门控收口"——每个标签有自己的头、自己的门控，
拒识的时候告诉用户该去哪个标签。

**6（1:50）** 鱼香肉丝不在食堂 20 道里，食堂模式明确拒识，不硬给答案；116 类模型能认出来，53.7%。

**7（2:10）** 这张不是菜。食物门控直接说"画面里没有菜"，连候选都不给。

**8（2:25）** 混合餐盘，一盘三样。炒青菜 65%、干煸豆角 65%、辣子鸡 51%，整盘 550 到 840 千卡。

**9（2:50）** 也说说失败的：汉堡认对了，但薯条被判成华夫饼，还多检出一块牛排。多标签的误检我们还在改。

**10（3:05）** 数字：623 张网图 95.7% 的 top-1，接受率 84.4%；只有一道菜的外部集 88.5%；
真实食堂托盘上整盘全对只有 6.3%，这是目前最大的短板，也是下一步要采数据的地方。

**11（3:25）** 四个模式、拒识、热量区间都已经在网页上跑起来了。谢谢。

## 4. 三条注意事项

1. **不要念推理耗时**。payload 里没有 `elapsed_ms`，网页上那个 1.25 s 是端到端含上传的，
   在录屏机器上会变。要讲速度就说"单张百毫秒级"。
2. **包子那张现在会放宽阈值**。`04_包子.jpg` 的域概率 0.9334 过了 0.90，阈值自动放宽到 0.36，包子 93.2% 被接受——
   可以讲"域头确信就放宽"。要讲保守，用 08 麻婆豆腐（域 0.8499 < 0.90，阈值仍是 0.4088）。
3. **混合模式的第二项可能是错的**。10 号镜头就是为此保留的：宁可演示一次误检，也不要把
   "多标签很准"讲成结论（`results/tables/mixed*` 的 plate-F1 是 54.5；搭配先验 A/B 版能到 56.3，但没上线，见 README 5.3 末尾）。
