# 最小复现路径（约 30 分钟，不含下载）

仓库里**没有权重文件**（每个 checkpoint 约 45 MB，被 .gitignore 排除），也**没有
Food-101 原图**（约 5 GB）。所以别人拿到仓库后能复现的是"从头训练 + 评估 + 起服务"
这条链，而不是"下载就能跑"。下面每一步都用仓库里现成的脚本，命令从仓库根目录执行。

## 0. 环境

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock   # 精确版本
# 或 requirements.txt（宽松版本下限）
```

要求 Python 3.11+；有 CUDA 时训练快 10 倍左右，CPU 也能跑完（12 epoch 的
ResNet-18 末段微调在 CPU 上约 40 分钟）。

## 1. 数据

```powershell
# 从 HuggingFace 镜像拉 Food-101（不需要 Kaggle 账号）
.venv\Scripts\python.exe scripts\fetch_food101_hf.py --out data/raw_hf --workers 4
# 划出 train/val/test 与食堂代理域（固定 seed，结果可复现）
.venv\Scripts\python.exe scripts\prepare_data.py --data-root data --seed 42
```

产出 `data/splits/{train,val,test,canteen_clean}`。代理域的构成见 README §5.6。

## 2. 训练 20 类主模型

```powershell
.venv\Scripts\python.exe scripts\run_all.py resnet18_last_stage_aug
```

等价于 `python -m foodcls.train --data-root ../data --arch resnet18 --mode last_stage
--epochs 12 --color-aug --out results/runs/resnet18_last_stage_aug`（在 `src` 下运行）。
只跑这一个配置约 6 分钟（GPU）。权重落在 `results/runs/<name>/best.pt`。

论文表 II 的六行就是 `scripts/run_all.py` 的六条命令；外部数据那行再加
`--extra-train data/splits/food101n_clean --extra-weight 0.5`。

## 3. 校准与评估

```powershell
.venv\Scripts\python.exe scripts\fit_temperature.py --workers 2 --run results/runs/resnet18_last_stage_aug
.venv\Scripts\python.exe scripts\benchmark.py          # → results/tables/benchmark.csv
.venv\Scripts\python.exe scripts\eval_real_photos.py   # 100 张自摄照片 + 六视图
.venv\Scripts\python.exe scripts\eval_wide_real.py     # 116 类模型在真实照片上的 89%
```

统计（bootstrap 区间与 McNemar 检验）读缓存的 logits，不需要 GPU：

```powershell
.venv\Scripts\python.exe results\_stats.py
```

## 4. 两个否决头的权重

门控与包装头的权重是纯 JSON（几百 KB），由下面的脚本从缓存特征重新拟合：

```powershell
.venv\Scripts\python.exe results\_gate_rebuild.py   # 抽 512 维池化特征
.venv\Scripts\python.exe results\_gate_final.py     # 食物门控 → tables/foodgate_linear.json
.venv\Scripts\python.exe results\_pkg_final.py      # 包装头   → tables/packaging_linear.json
```

（这些脚本住在 `results/` 而不是 `scripts/`，是因为它们依赖缓存的特征文件；
`.gitignore` 里 `results/_*` 只忽略结果图，脚本本身是入库的。）

## 5. 起网页

```powershell
cd src
$env:FOODCLS_CKPT = "..\results\runs\resnet18_last_stage_aug_f101n\best.pt"
$env:PORT = "8000"
..\..\.venv\Scripts\python.exe -m foodcls.app
```

部署用的是 `resnet18_last_stage_aug_f101n`，因为食物门控与包装头是在它的池化特征上
拟合的；换成别的主干而不同时换 `FOODCLS_GATE` / `FOODCLS_PACK`，两个头会静默失效
（`/api/health` 里 `enabled` 变 false）。打开 http://127.0.0.1:8000 。可选环境变量：
`FOODCLS_HOST`（默认 127.0.0.1）、
`FOODCLS_TOKEN`（访问口令）、`FOODCLS_GATE`、`FOODCLS_PACK`。

## 6. 测试

```powershell
.venv\Scripts\python.exe -m pytest tests -q      # 34 passed
```

API 测试故意不加载权重（CI 里没有 checkpoint），只覆盖类别表、纠正校验和
上传像素上限；端到端行为见 `results/REPORT_*.md`。
