# 微信小程序上手指南

`miniprogram/` 已经是一个**能直接跑**的原生小程序工程：单页、两个模式（单菜识别 / 混合餐盘）、份量切换、克数重算、整盘合计。它自己不跑模型，只是把照片传给本项目的 FastAPI 服务，接口和网页版完全一样。

## 0. 先理解这条链路

```
手机拍照 → wx.uploadFile → https://你的地址/api/predict 或 /api/mixed/predict
                              ↓
                     电脑上的 FastAPI + PyTorch（GPU/CPU）
                              ↓
              JSON：Top-3、概率、热量区间、范围提示
```

所以小程序能不能用，取决于**手机能不能访问到那台跑模型的电脑**。开发阶段用"同一 Wi-Fi + 电脑局域网 IP"，正式用"公网 HTTPS 域名"。

## 1. 工程结构（改代码就看这几处）

| 文件 | 作用 |
|---|---|
| `app.json` | 页面注册（只有 `pages/index/index`）、导航栏标题"食堂热量估算" |
| `project.config.json` | 工程配置；`appid` 预置为 `touristappid`（游客/测试号），`setting.urlCheck: false`（默认不校验域名，方便本地调试） |
| `config.js` | **只有一行要改**：`BASE_URL` —— 服务地址 |
| `pages/index/index.js` | 逻辑：`onLoad` 调 `/api/health` 看混合模型是否加载；选图 `wx.chooseMedia`；上传 `wx.uploadFile`；混合模式重算 `/api/mixed/total` |
| `pages/index/index.wxml` | 结构：模式切换、拍照区、份量三段、克数输入、Top-3 卡片、混合餐盘的每个菜 + 整盘合计 |
| `pages/index/index.wxss` | 样式（蓝色主题，和网页版一致） |

接口约定（写死在 `index.js`，要和后端一致）：

- `GET /api/health` → `{ok, mixed_enabled, ...}`
- `POST /api/predict`，multipart 字段名 **`file`**，附带 `portion`（small/normal/large）、可选 `grams`
- `POST /api/mixed/predict`，字段同上，返回 `plate.parts[]` 和 `plate.total`
- `POST /api/mixed/total`，JSON `{portion, parts:[{class, prob, portion, grams}]}`，用于改份量/克数后重算

## 2. 装微信开发者工具

1. 打开 <https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>，下载 **稳定版 Windows 64**。
2. 安装后启动，用**微信扫码登录**（不登录不能预览/上传，但可以先用模拟器）。

## 3. 先把后端跑起来

在小程序之前，确认电脑上的服务是通的：

```powershell
cd "E:\项目作业\food_project"
powershell -ExecutionPolicy Bypass -File scripts\start_demo.ps1
```

看到 `http://127.0.0.1:8000` 和局域网地址就算好了。浏览器打开该地址能上传图片识别即可。

## 4. 导入项目

开发者工具首页 → **导入项目**：

- **目录**：选 `food_project\miniprogram`（不是 `food_project`）
- **AppID**：默认已是 `touristappid`（测试号），没有小程序账号也能用；有自己的 AppID 就填自己的
- **后端服务**：选"不使用云服务"
- 点"导入"。

## 5. 改 `config.js`：连到你的服务

打开 `miniprogram/config.js`，按场景改 `BASE_URL`：

| 场景 | BASE_URL 写什么 | 说明 |
|---|---|---|
| 只在电脑模拟器里看 | `http://127.0.0.1:8000` | 模拟器里的 127.0.0.1 就是电脑本机 |
| 手机真机预览（同一 Wi-Fi） | `http://电脑局域网IP:8000`，如 `http://10.17.204.21:8000` | 用 `ipconfig` 看"无线局域网适配器 WLAN"的 IPv4；服务要监听 0.0.0.0（`start_demo.ps1` 默认就是） |
| 走公网固定地址 | `https://food.你的域名.com` | 见 `docs/永久公网地址.md`；**必须是 https** |

改完保存，开发者工具会自动热重载。

> 手机和电脑必须同一个 Wi-Fi，且 Windows 防火墙放行 8000（`start_demo.ps1` 会尝试加规则）。校园网常把设备隔离（AP isolation），如果手机连不上但电脑能开，换手机热点给电脑连，通常就好了。

## 6. 关掉域名校验（开发阶段）

小程序默认只允许请求"已备案 + 已在小程序后台配置"的 HTTPS 域名。本地 `http://IP` 会被拦。

**方式一（推荐）**：工程已预置 `project.config.json` 的 `setting.urlCheck: false`；导入后仍建议确认一次：
开发者工具右上角 **详情** → **本地设置** → 勾选 **"不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书"**。

**方式二**：真机预览时这个设置同样生效（开发版/体验版调试用）。

> 这个开关**只对开发版/体验版调试有效**。正式发布（线上版）必须配置合法域名，见第 10 节。

## 7. 在模拟器里试用

1. 点"选择照片"——模拟器会弹文件选择框，选 `data/splits/canteen_clean` 或 `results/figures` 里的菜品图。
2. 看"识别结果 · Top-3"：中文名、类别概率、热量区间（kcal_low–kcal_high）、克数、每 100g 热量。
3. 点"份量"的小份/常规/大份，结果会重算；"重量"填实际克数（如 250）回车，也会按你的克数重算。
4. 切到"混合餐盘"tab：上传拼盘图（如 `data/splits/mixed/mix_05_ramen_dumplings.jpg`），会列出每样菜，每样可单独调份量和克数，底部是"整盘合计"。
5. 如果页面顶部出现橙色警告（"这张图可能不在支持的 20 类里"），说明开集门控判定为范围外，结果仅供参考——这是预期行为。

> 混合 tab 是灰的？说明后端没加载多标签权重（`/api/health` 的 `mixed_enabled=false`），检查 `results/runs/resnet18_multilabel_aug/best.pt` 是否存在，或用 `start_demo.ps1 -MixedCkpt ...` 指定。

## 8. 真机预览

1. 确认 `config.js` 的 `BASE_URL` 是电脑的**局域网 IP**（不是 127.0.0.1），手机和电脑同一 Wi-Fi。
2. 开发者工具顶部 **预览** → 生成二维码 → 手机微信扫码。
3. 手机上会打开"开发版"小程序，拍照/相册选图，识别结果和模拟器一致。

### 真机连不上排查

| 现象 | 检查 |
|---|---|
| "连不上服务" | 手机浏览器先访问 `http://电脑IP:8000` 能不能开。打不开 = 网络/防火墙问题，不是小程序问题 |
| 手机浏览器能开、小程序报 `url not in domain list` | 回第 6 节勾选"不校验合法域名"，重新"预览" |
| 请求超时 | 校园网 AP 隔离；换手机热点；或确认防火墙允许 8000（`start_demo.ps1` 已尝试） |
| 上传失败（`uploadFile:fail`） | `config.js` 里还是 127.0.0.1；或服务没监听 0.0.0.0 |
| 返回 422 | 字段名必须是 `file`（`wx.uploadFile` 的 `name: "file"`），不要改成 `image` |

## 9. 换成公网固定地址

按 `docs/永久公网地址.md` 配好 Cloudflare Named Tunnel（或 Tailscale Funnel / ngrok）后：

1. 把 `config.js` 的 `BASE_URL` 改成 `https://food.你的域名.com`；
2. 开发阶段仍勾着"不校验合法域名"就能在 4G 下预览；
3. 想让**正式版**也能用，必须走第 10 节的合法域名配置（域名要备案）。

## 10. 正式发布要做什么（备案是硬门槛）

个人也能注册和发布小程序，但"能联网"的小程序有几个硬条件：

1. **注册小程序**：<https://mp.weixin.qq.com> → 立即注册 → 小程序 → 邮箱激活 → 主体类型选"个人"（需身份证 + 人脸核验）。个人主体不能做部分类目（如医疗、金融），做"教育/工具"类的识别 demo 没问题。
2. **域名备案 + HTTPS**：小程序后台配置的服务器域名必须是**已 ICP 备案**的域名，且支持 HTTPS（443 端口，不能带路径/端口号）。Cloudflare 隧道 + 自己备案的域名可以满足；`.ts.net`、`.ngrok-free.app` 都不行（不是你的备案域名）。备案在阿里云/腾讯云"ICP 备案"里提交，通常 7–20 个工作日。
3. **配置服务器域名**：小程序后台 → **开发** → **开发管理** → **开发设置** → **服务器域名**：
   - `request 合法域名`：`https://food.你的域名.com`
   - `uploadFile 合法域名`：同上
   - 每月修改次数有限，别乱填。
4. **上传代码**：开发者工具右上角"上传" → 填版本号（如 1.0.0）→ 到小程序后台"版本管理"里能看到开发版本。
5. **提交审核**：后台"版本管理" → 提交审核 → 选类目（教育 > 教育工具 / 工具 > 效率）、填页面信息、测试账号（本项目无需登录）→ 等 1–7 天。
6. **发布**：审核通过后点"发布"，线上版即可被搜索/分享。之后每次改代码要重新上传 + 审核（可先用"体验版"给老师试）。

> 只想交作业：**不用发布**。开发版/体验版 + "不校验合法域名" + 公网 HTTPS 地址就足够演示，老师扫码即可体验。

## 11. 常见报错对照表

| 报错 | 原因 | 解决 |
|---|---|---|
| `request:fail url not in domain list` | 域名没配置 / 没勾"不校验合法域名" | 开发阶段勾选；正式版配置合法域名 |
| `request:fail ssl hand shake error` | 证书链不完整/自签名 | 用正规 CA 证书（Cloudflare 隧道自带） |
| `request:fail timeout` | 网络不通、AP 隔离、防火墙 | 手机浏览器先验证；换热点；放行端口 |
| `uploadFile:fail Error: 系统错误` | 后端崩了或返回非 JSON | 看后端控制台；浏览器直接试网页上传 |
| `422 Unprocessable Entity` | multipart 字段名不对 | `wx.uploadFile` 的 `name` 必须是 `file` |
| 页面白屏 | 目录选错（选了 `food_project` 而不是 `miniprogram`） | 重新导入，目录必须含 `app.json` |
| 混合 tab 点了提示"混合模型未加载" | 后端 `mixed_enabled=false` | 检查多标签 `best.pt`，或用 `-MixedCkpt` 指定 |
| 真机预览二维码扫不开 | 没登录 / 没勾选预览权限 | 开发者工具重新登录，用"预览"而不是"真机调试" |

## 12. 想加功能从哪下手

- **加 116 类宽模型 tab（Food-101 101 类 + 15 道中餐）**：`index.js` 里已有 `mode` 切换的骨架。新增 `mode: "wide"`，选图后调 `/api/wide/predict`（字段同样 `file`），返回的 `top3` 结构和单菜接口一致；顶部模式条加一个 `view`（`index.wxml` 第 3–6 行）。注意 101 类的热量区间来自 `data/calories_wide.json`，后端已按类返回。
- **改配色/布局**：`index.wxss`（主色 `#2f6df6` 附近）。
- **加历史记录**：`wx.setStorageSync("history", ...)`，在 `showSingle`/`showMixed` 里存。
- **加拍照后自动裁剪**：`wx.chooseMedia` 拿到的 `tempFilePath` 可直接用 canvas 2d 裁剪再上传。
