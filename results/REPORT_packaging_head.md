# 包装照否决头（packaging head）

2026-11-15。目标：修掉"冷冻披萨盒 → pizza 98%"。

## 问题

- 20 类头对包装照很自信（盒盖上印着披萨，它就是披萨），食物门控也判"是食物"——两个模型都没错，是问错了问题。
- 原来的 `src/foodcls/packaging.py` 是 numpy 启发式（长直强边缘比例 + 细纹理密度，`STRAIGHT_MIN=0.020`、`EDGE_MAX=0.060`），在 62 张超市包装照上命中 **0/62**，而且只在照片已被判 out-of-scope 时才改文案。
- 归档批次实测（`results/tables/v3_api.json`，改之前）：36/62 被判"在范围"，pizza 98%、ice_cream 87%。

## 方法

和食物门控同一套做法，一个线性头换掉启发式：

| 项目 | 值 |
| --- | --- |
| 特征 | 512 维 avgpool，取**整帧**视图（三取景里的第 2 个，square） |
| 模型 | 逻辑回归，C=0.01，class_weight=balanced |
| 正样本 | 79 = 负样本库 17 张包装 + 归档 62 张商品照（sha256 去重后） |
| 负样本 | 3,700 张食物照（train 2,000 / clean 1,000 / 真实 100 / test 600） |
| 阈值 | p ≥ 0.80，写在权重文件里（重训不会静默沿用旧点） |
| 额外前向 | 0（六视图那一次推理已经算了 512 维） |

## 留出评估（对 62 张做 5 折，17 张旧包装留作另一域）

| 取景 | v3 折外 AUC | 召回 @p0.8 | 旧包装留出召回 | 食物误标（train/clean/真实/test） |
| --- | ---: | ---: | ---: | --- |
| v0 中心裁剪 | 0.996 | 76% | 65% | 0.55/0.50/0.00/0.00 % |
| **v1 整帧（采用）** | **0.994** | **79%** | **76%** | 0.60/0.70/0.00/0.17 % |
| v2 宽裁剪 | 0.992 | 79% | 71% | 0.55/0.60/0.00/0.00 % |
| 三取景平均 | 0.995 | 77% | 71% | 0.65/0.90/0.00/0.00 % |
| 三取景拼接 | 0.996 | 73% | 71% | 0.30/0.10/0.00/0.00 % |

选整帧：包装是"整件东西"，裁剪会切掉标签；拼接没有明显收益，还多一倍权重。

## 端到端（走 HTTP，`results/tables/pkg_sweep.json`）

| 集合 | n | 判"在范围" | 包装标记 | 备注 |
| --- | ---: | ---: | ---: | --- |
| 归档 v3 商品照 | 62 | **0**（改前 36） | 50 | 另 12 张门控本就判非食物，走通用文案 |
| 负样本库包装照 | 17 | **0** | 1 | 其余被门控拒，文案不专门 |
| 真实食堂菜 | 100 | 95 | **0** | 与加头之前完全一致，无一张被误标包装 |
| 真负样本 | 138 | 8 | 4 | 8 张是改标后的食物（001–004/009/010）+ 104/130 |
| 代理域抽样 | 300 | 285 | 0 | |

否决只在食物门控已判"是食物"时生效：门控说没有食物时它自己的文案更准（46 个被标包装的负样本里 43 个属于这种）。

示例（`results/_pkg_demo.py`）：

```
results/_discarded_v3/pizza/IMG_pizza_0003.jpg
  in_scope False  p_pack 0.9417  p_food 0.9991  top1 披萨 0.998
  message: 这张照片看起来是商品包装或食品标签（比如包装盒正面印着的菜），不是一个餐盘。
```

## 局限

- 62 张正样本是同一种拍法（商品正面、白底、印刷体）。"这一类包装照"召回 79% 可信；换成实拍货架包装，只有 1/17 会被专门标成包装（其余仍被门控以"没找到菜"拒掉，文案不专门）。
- 提升方向是补实拍包装负样本（货架、外卖袋、保鲜膜托盘、饮料罐），不是重训这个头——79 个正样本已经把 512 维线性层的容量吃满了。
- 包装照的判定与"是不是食物"是两件事：这头在负样本库上会误标餐巾/菜单牌（4/138），但因为只在门控通过后才生效，用户看不到这些误标。
